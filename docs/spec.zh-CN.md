# Title Dedup：设计说明

[English version](./spec.md) · [Русская версия](./spec.ru.md)

## 目标

当目标源有新文章到达，而同一规则组的参考源中已有归一化后标题相同的文章时，把这篇目标源文章标记为已读。

## 范围

- 支持多个规则组，每个规则组包含多个参考源和多个目标源
- 默认单向生效：参考源影响目标源，反之不成立
- 同一个订阅可以既是参考源又是目标源。把一个网站的所有栏目同时列在两边，每条新闻最先到达的那一份保持未读，之后的每一份都标为已读
- 基于标题归一化后的完全一致判断

## 不做的事

- 不做全文相似度去重
- 不做跨语言去重
- 不修改 FreshRSS 核心
- 不做客户端侧去重

## 工作方式

### 新文章（`entry_before_add` 钩子）

该钩子只对新文章触发，并且在用户的过滤动作之后执行，所以已被过滤规则标为已读的文章按已读处理。

FreshRSS 在一次刷新结束前把新文章保存在 `_entrytmp` 中，之后才移入 `_entry`。因此查询覆盖这两张表，同一次刷新中拉取到的多份副本也能互相比对。

在一次请求中，第一篇与某个规则相关的新文章到达时，加载该规则所有订阅在回看天数内的标题，只加载一次，之后在内存中持续更新。每篇新文章按到达顺序处理：

1. 如果文章属于目标源、未读，并且其标题已在另一个参考源中出现过，它就是重复文章，标为已读。
2. 如果文章属于参考源、未读，且自身不是重复文章，则把其他订阅中同标题的未读目标源文章标为已读（参考源的这一份比它们晚到）。
3. 记录该标题在其所属订阅中已出现；未被判为重复的未读目标源文章也会被记录，以防它的参考源之后才到。

已读文章只作为比对依据，不会把其他文章标为已读。否则，被上一次处理标为已读的副本可能会把保留下来的原文也标为已读。

已知文章的更新版本会被忽略。

### 标题归一化

先解码 HTML 实体，删除不可见的格式字符（软连字符、零宽空格）。然后按规则设置：

- 空白：连续的空白字符压缩为一个空格；
- 大小写：转为小写，`ё` 视同 `е`；
- 标点：标点和装饰性符号连同两侧空白替换为一个空格，所以 `A—B` 与 `A — B` 相同。货币符号和数学符号保留，因此 `100$` 与 `100€`、`C++` 与 `C` 仍然不同。

### 一次性回扫（`freshrss_user_maintenance` 钩子）

实际生效的规则发生变化后（重命名规则或添加空规则不算），下一次维护会按到达顺序（按文章 ID）重放回看天数内的已有文章，逻辑与上面相同。之后的维护不再执行任何操作，所以用户手动标回未读的文章会保持未读。以后每次修改规则都会再回扫一次，已经去重的文章不会改变。

## 配置

按用户保存，以 JSON 形式存放在扩展的用户配置中。每个规则组包含：

- `name`
- `enabled`
- `source_feed_ids`、`source_feed_names`
- `target_feed_ids`、`target_feed_names`
- `lookback_days`
- `normalize_whitespace`
- `normalize_case`
- `strip_punctuation`

订阅名在读取规则时解析为 ID，解码 HTML 实体后按不区分大小写的方式匹配。配置页只保存订阅 ID。

0.1 版本把规则保存在系统配置中；在用户保存配置之前，仍会从那里读取。

## 文件

- `metadata.json`
- `extension.php`：钩子、配置表单处理、配置存储
- `configure.php`、`configure.phtml`：配置页
- `static/configure.css`、`static/configure.js`：配置页的样式和脚本。FreshRSS 的内容安全策略（CSP）会拦截内联样式和脚本，所以放在单独文件中；脚本也会加载到扩展列表页，因此配置在侧边栏中同样可用
- `lib/DedupService.php`：去重逻辑
- `lib/DedupDAO.php`：数据库查询
- `lib/TitleNormalizer.php`
- `lib/RuleRepository.php`：规则的解析与校验
- `i18n/`：翻译
- `examples/sample-config.json`

## 风险

- 标题完全一致不等于同一条新闻，可能把无关文章标为已读
- 改写过标题的转载无法识别
