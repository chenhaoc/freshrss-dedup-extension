# FreshRSS Title Dedup

Расширение FreshRSS для поиска дублей между лентами по заголовку.

Другие языки: [English](./README.md) · [中文](./README.zh-CN.md)

Когда в целевую ленту B приходит новая статья, расширение помечает её прочитанной, если такой же заголовок уже был в ленте-источнике A.

## Когда пригодится

- Несколько лент публикуют одну и ту же новость: например, разделы одного сайта
- Нужно оставить непрочитанным основной источник и пропускать перепечатки
- Нужны правила для выбранных лент, а не одно глобальное правило на все

## Возможности

- Односторонние правила: A влияет на B, но не наоборот
- Лента может быть одновременно источником и целью. Если указать все разделы сайта с обеих сторон, непрочитанной останется только первая пришедшая копия каждой новости
- Несколько правил
- Несколько лент-источников и целевых лент в каждом правиле
- Нормализация заголовков: пробелы, регистр, пунктуация, каждая включается отдельно
- Порядок прихода не важен: копия в цели гасится, пришёл ли источник раньше, в том же обновлении или позже
- Разовая проверка уже накопленных статей после сохранения правил
- Правила у каждого пользователя свои
- Страница настроек: ленты сгруппированы по категориям, есть фильтр и массовый выбор; переведена на русский, английский и китайский

## Как работает

- Заголовок новой статьи сравнивается с заголовками лент-источников за период поиска. В том числе со статьями, пришедшими раньше в том же обновлении, которые FreshRSS ещё не перенёс в основную таблицу. При совпадении новая статья в целевой ленте помечается прочитанной.
- Когда приходит новая непрочитанная статья источника, непрочитанные статьи целевых лент с тем же заголовком помечаются прочитанными. Прочитанная статья служит только образцом и никого не гасит.
- Заголовки загружаются один раз на правило за запрос, поэтому обновление стоит один запрос к базе на правило.
- После сохранения правил при ближайшем обновлении один раз проверяются все статьи за период поиска. Дальше проверяются только новые, поэтому статья, которую вы вручную вернули в непрочитанные, такой и останется.

## Установка

Корень репозитория — это и есть расширение. Склонируйте его в каталог `extensions/` FreshRSS и включите `Title Dedup` в настройках расширений пользователя:

```sh
cd /path/to/FreshRSS/extensions
git clone https://github.com/chenhaoc/freshrss-dedup-extension.git xExtension-TitleDedup
```

Обновление — `git pull` в `extensions/xExtension-TitleDedup`.

Проверено на FreshRSS 1.30.4 (PHP 8.3, PostgreSQL).

### Обновление с 0.1

Версия 0.1 была системным расширением, 0.2 — пользовательское. После обновления включите его заново в настройках расширений каждого пользователя. Старые правила читаются из системной конфигурации, пока пользователь один раз не сохранит настройки.

## Использование

1. Откройте настройки расширения: в боковой панели или кнопкой «Открыть на отдельной странице», если нужно больше места.
2. Отметьте ленты-источники. Введите в фильтр часть названия ленты или категории (например, имя сайта) и нажмите «Выбрать показанные», чтобы отметить все подходящие ленты разом. В свёрнутом виде список показывает выбранные ленты.
3. Отметьте целевые ленты или включите «Целевые ленты совпадают с источниками», чтобы искать дубли внутри группы лент.
4. Задайте период поиска и параметры сравнения заголовков.
5. Сохраните. Кнопка «Добавить правило» добавляет ещё одно правило.

## Поля правила

Правила хранятся в JSON в пользовательской конфигурации расширения (пример: [examples/sample-config.json](./examples/sample-config.json)). У каждого правила:

- `name`: название правила, видно только в настройках
- `enabled`: по умолчанию `true`
- `source_feed_ids`: ленты-источники A
- `source_feed_names`: названия лент-источников, можно сочетать с `source_feed_ids`
- `target_feed_ids`: целевые ленты B
- `target_feed_names`: названия целевых лент, можно сочетать с `target_feed_ids`
- `lookback_days`: сравнивать только за последние N дней, от 1 до 3650, по умолчанию 14
- `normalize_whitespace`: схлопывать повторяющиеся пробелы, по умолчанию `true`
- `normalize_case`: не учитывать регистр, `ё` равна `е`, по умолчанию `true`
- `strip_punctuation`: не учитывать пунктуацию и декоративные символы; в JSON по умолчанию `false`, у нового правила на странице настроек включено

Правило без источников или без целей ничего не делает. Названия лент сопоставляются без учёта регистра при чтении правил. Сохранение со страницы настроек записывает только ID лент: названия лент, которых в этот момент нет, отбрасываются.
